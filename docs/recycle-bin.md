# 持久回收站

默认保留 3 天，可在“我的 → 回收站”选择 3、7、30 天。期限针对全部回收站记录，从每条记录的删除时刻计算；缩短期限会在确认后立即清理超过新期限的记录。

## 本地存储与备份

继续使用 SharedPreferences 的 `yanli_records_v1`，在原 v3 备份结构顶层增加 `localRecycleBin`（版本、保留天数、删除记录与时间、删除时受影响的关联）。有效记录、回收站与期限在同一字符串中单次保存，经原 StorageSafety 串行写入及 writeSnapshot 注入路径提交。成功确认后才更新界面；失败保留两部分原状态供重试，不存在先删 active 再保存 trash 的两次写入窗口。

旧 v1/v2/v3 数据直接读取。原 decodeBackup 仍仅解析有效记录；普通复制、文件导出备份只含有效记录，不含回收站和本地期限。损坏的回收站使整个本地快照进入原坏数据保护流程，暂停修改，可复制或导出原始数据。恢复备份时仍使用原有效记录严格验证。

清空全部数据及恢复备份会在同一次快照提交中清空回收站，确认界面有说明，避免之后从旧回收站恢复已清空的数据。它们保留当前保留天数设置。

## 恢复与清理

恢复沿用 domain 的 RecordDeletion.restore，按当前有效记录合并，保留后续编辑和新增记录，不复活另一条已删除记录，也不重复占用同一导师事项来源。若历史关联因来源消失、日期变化或循环导致严格校验不通过，则保留当前有效记录并恢复不带历史关联的目标记录。

启动、打开回收站、返回前台，以及运行期间每分钟检查到期记录。到期按删除时刻加完整的 24 小时天数计算；自动清理写入失败时保留快照，之后的触发会重试。到期记录不能恢复。应用关闭或系统暂停执行时不运行后台任务，下次打开或恢复执行后清理；不需要网络。

删除提示有撤销入口，约 3 秒后主动移除，也覆盖 accessibleNavigation 导致带操作 Snackbar 无限停留的情况。提示消失后仍可在回收站恢复。单条永久删除、清空回收站均需确认。

## 限制

单 key 快照消除应用层多 key 不一致，但 SharedPreferences 不提供数据库级断电持久性保证。写入返回失败表示未确认；若底层实际已落盘后报错，重启可能读到完整的新快照。设备时钟变化会影响按时间到期的判断。此功能不承诺介质层安全擦除或删除用户已另行导出的文件。旧版本应用若写回本地数据，会丢弃其不认识的回收站字段，因此应避免降级使用。
